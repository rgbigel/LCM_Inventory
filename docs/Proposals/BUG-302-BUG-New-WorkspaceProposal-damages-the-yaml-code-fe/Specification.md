## 1. Executive Summary & Intent

`New-WorkspaceProposal` in `LCM_Inventory/modules/ProposalManager.psm1` builds the Specification template in an expandable here-string (`@"..."@`). In such a string the backtick is the escape character, so the fences on source lines 218 (opening yaml fence) and 230 (closing fence) are expanded to a single backtick (`` `yaml `` and `` ` ``). Every proposal bundle created by the function has a broken metadata block that renders as plain text. Found while creating CRP-301 (2026-10-21).

A read-only scan of `docs/Proposals/*/Specification.md` in all top-level repositories found 18 damaged files out of 113 (list in section 5).

## 2. Gate 0 Contract

### Target State

1. A Specification.md generated by `New-WorkspaceProposal` contains an intact opening yaml fence and closing fence.
2. The 18 already damaged Specification files are repaired, or the operator explicitly decides to leave them (decision at review).

### Invariants and Exit Criteria

- The only change in `ProposalManager.psm1` is the fence handling in the Specification template. Proposed form: define `$fence = '```'` before the here-string and use `${fence}yaml` and `${fence}` in it. No other template text, no other function changes.
- A Pester test generates a Specification in a scratch location and asserts that it contains a line equal to the opening yaml fence and a closing fence line, and no line consisting of only a single backtick followed by text. The test fails before the fix and passes after it.
- Repair of existing files (if approved) changes only the damaged fence lines (the line `` `yaml `` becomes the opening yaml fence; the matching closing single-backtick line becomes the closing fence). Content and line endings are otherwise untouched; each repaired file is listed in the report.
- The Specification files of BUG-302 and CRP-301 are already corrected by hand and are not counted in the repair.
- Changes pass the readiness and syntax gates (AST check) and the Beyond Compare review before commit. No push.

### Explicit Non-Goals

- Redesign of the proposal templates, Baseline-Version handling, or any other function in `ProposalManager.psm1`.
- Changing proposal states, ledgers, or history.
- Repairing files outside `docs/Proposals/*/Specification.md`.
- Default Non-Goal: cause no havoc; ask rather than invent or infer, and avoid unnecessary complexity.

## 3. Technical Requirements & Invariants

- Invariant 1: Must conform to LCM governance standards (`modules/` is a protected area: CM proposal and review gate apply).
- Invariant 2: PowerShell rules apply (`RULE-PS-021` AST gate before handoff; CRLF, UTF-8 encoding as the file already uses).
- Invariant 3: Note that tool-generated Specification text for this very proposal is damaged again by the bug; it was replaced by hand with correct fences.

## 4. Verification and Review

- The Pester test above (red before, green after).
- Create a throw-away proposal in a scratch repository path, inspect the yaml block, delete it.
- Re-run the scan: expected result 0 damaged files (or only those the operator chose to leave).
- Beyond Compare review of the complete change set.
